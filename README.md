# Tangebricks

> **Status:** pre-1.0 beta. **Not production-ready.** Do not put real customers' data or money on it yet. Payments run in test mode only.

Tangebricks is an open-source platform for building multi-tenant SaaS backends on the Cloudflare edge (Workers, D1, Workflows, Durable Objects) from reusable **bricks**: wallet, auth, workspaces, webhooks, audit trail and more. A blueprint names the bricks and entities you want; the assembler turns it into a Worker project, and the deploy tooling publishes it into **your own Cloudflare account**. A visual studio and an MCP endpoint let people and AI agents edit the same blueprint.

- **Licence:** [Apache-2.0](LICENSE).
- **Name:** the project is being renamed to Tangebricks. The repository is `tangebricks/tangebricks`; the code and the packages still use the old names (`projectx`, `@poc/*`), and that rename is planned and has not happened yet.
- **Where it runs:** your own Cloudflare account. There is no hosted service.
- **Payments:** test mode only (beta). The wallet has no default payment gateway: until one is configured its payment routes answer 503 `NOT_CONFIGURED`. A Stripe adapter exists in `packages/gateway-adapters`; no live payment has been taken.

## What does not work yet

- **Quarantined bricks** (listed above) are unsafe or stubs. They are hidden from the default catalog and from the MCP `list_bricks` answer (story 0.11) and must not be used.
- **Studio deploys** use an in-memory mock of the Cloudflare API. Only the scripted provisioner (`pnpm poc:deploy`) has deployed for real, in the live runs listed above.
- **Restore** of a D1 database has only been drilled against a fake Cloudflare.
- **The MCP endpoint and the self-correction evaluation** have been measured with scripted sessions, not with a language model.
- **Live evidence** comes from single runs on one day; see the live-evidence table for dates and staleness.

The full list of known risks, and the stories that fix them, is in the [threat model](docs/threat-model.md).

## How the evidence works

The project started as a measured proof of concept. Each architectural claim is a hypothesis in [`hypotheses.json`](hypotheses.json) with pass and kill thresholds; `pnpm poc:verify` measures them and writes `evidence/verdicts.json`, and [`PROOF.md`](PROOF.md) is generated from that file.

- **Thresholds.** No pass or kill threshold in `hypotheses.json` has changed since it was committed. For H0–H3 the thresholds and the code arrived in the same commit, so they were not set in advance. H4 was retired ([docs/retired-hypotheses.md](docs/retired-hypotheses.md)).
- **Offline re-measurement.** `pnpm proof:check` re-runs the offline hypotheses into a temporary directory and compares them with `evidence/verdicts.json`, checks the hash of the inputs, compares `PROOF.md` with what `pnpm proof:generate` would write, and checks the "What works today" section above.
- **Live results are recorded, not re-run.** H10, H11, H12, the hosted half of H5 and the deployed half of H9 rest on recorded live runs in `evidence/deployed/`. The verifier only re-reads those files.
- **Live evidence integrity.** `evidence/deployed/integrity.json` holds the sha256 and run timestamp of every live result file. `pnpm proof:check` fails when a result file changes while its run timestamp does not (an edit without a re-run), or when a result file has no entry. After a genuine live re-run, record it with `pnpm evidence:record-live`, then run `pnpm readme:generate`. One past hand edit is recorded rather than hidden: H12's result file was edited on 2026-10-28 without a re-run, and it is marked "hand-edited, unverified" above.
- **Releases.** `pnpm release:check --ref <commit>` fails when live evidence predates the release commit and the README does not label it stale. Changes are listed in [CHANGELOG.md](CHANGELOG.md).
- **Refreshing evidence.** `pnpm evidence:refresh` regenerates the local evidence, `PROOF.md` and the section above in one pass on a clean tree, then runs the checks. It never touches `evidence/deployed/`.

## Repository layout

```text
projectx-poc/
├── bricks/          # the bricks: one folder per brick (manifest, src, migrations, tests); e.g. bricks/credit-wallet
├── packages/
│   ├── assembler/   # blueprint -> Worker project (deterministic, offline)
│   ├── blueprint/   # blueprint operations, revisions, revert
│   ├── runtime/     # graph interpreter (no code generation)
│   ├── sdk/         # tenant context, route contracts, graph validator
│   ├── mcp-server/  # MCP endpoint (Streamable HTTP) over the blueprint
│   ├── deploy/      # Cloudflare REST provisioner, bundler, Workflow runner
│   ├── integrations/# OpenAPI importer and integration packs
│   ├── telemetry/   # events and redaction
│   ├── core-nodes/  # first-party workflow nodes: triggers, logic, transforms, batch, HTTP
│   ├── gateway-adapters/ # payment gateway adapters (Stripe) for the credit wallet
│   ├── dafthunk/    # not in the repository: the vendored Dafthunk code was removed (H4 retired); a local folder may remain
│   └── harness/     # hypothesis register, verdict rules, evidence recorder
├── apps/
│   ├── studio-api/  # studio backend
│   └── studio-web/  # studio frontend (React Flow)
├── scripts/         # verification, evidence, deploy and check scripts
├── evidence/        # measured evidence; evidence/deployed holds recorded live runs
├── hypotheses.json  # the hypothesis register
└── PROOF.md         # generated from evidence/verdicts.json
```

The credit wallet keeps a **single-entry** ledger: one `credit_ledger` row per change, with the balance after it.

## Quickstart

Prerequisites: Node.js 24 or later, pnpm 10.18.

```powershell
pnpm install --frozen-lockfile

# Run the complete test suite
pnpm test

# Typecheck every package and client
pnpm typecheck

# Local gate before a pull request: typecheck plus the tests your change affects
pnpm check:changed
```

### Evidence and proof commands

```powershell
pnpm poc:verify            # measure every hypothesis and write evidence/verdicts.json
pnpm poc:verdict           # print the register's decision
pnpm proof:check           # re-measure offline, check PROOF.md, live-evidence integrity and the README section
pnpm readme:generate       # rewrite the "What works today" section from evidence
pnpm readme:check          # fail if that section differs from the evidence
pnpm evidence:check        # check evidence provenance stamps
pnpm evidence:record-live  # record a genuine live re-run in evidence/deployed/integrity.json
pnpm release:check         # fail if live evidence older than the release commit is not labelled stale
```

### Live deploy and teardown

The live scripts (`pnpm poc:deploy`, `pnpm poc:graphs`, `pnpm poc:h5-hosted`, `pnpm poc:deploy:mcp`) need a Cloudflare API token for your own account in an env file outside the repository. To remove what they created:

```powershell
# Dry run: lists the resources in the deployment ledger
node "--env-file=path/to/.env" scripts/poc-teardown.ts --state-dir path/to/poc-state

# Remove every resource listed in the ledger
node "--env-file=path/to/.env" scripts/poc-teardown.ts --state-dir path/to/poc-state --yes
```
